# TIU GO 🛗

Мини-приложение для мониторинга лифтов Тюменского индустриального университета.
Работает **и в Telegram, и в MAX** — один общий фронтенд, два независимых бота.

Пользователь открывает мини-апп из бота и видит все **шесть лифтов** сразу:

- на каком этаже находится каждый лифт;
- сколько человек в кабине (и не переполнена ли она);
- сколько человек ждут в холле у лифта — это видит камера;
- рекомендацию по каждому лифту: **ждать** или **идти по лестнице**.

Тап по карточке открывает экран лифта с кадром камеры из холла,
на котором ИИ подсвечивает рамками ожидающих людей.

> Камеры стоят **не в кабине, а в холле** у лифтов — они снимают зону ожидания.
> Данные пока тестовые (мок-симуляция обновляется каждые 3 секунды);
> реальные камеры подключим позже, формат ответа API менять не придётся.

---

## Возможности

**Мониторинг**

- шесть лифтов на одном экране, карточки в две колонки, обновление раз в 3 секунды;
- текущий этаж, заполненность кабины и очередь в холле по каждому лифту;
- шахта с кабиной, которая плавно переезжает между этажами, и стрелка направления;
- экран лифта с кадром камеры из холла и рамками детекции ИИ.

**Подсказки**

- **выбор этажа назначения** на экране лифта — от него считается всё остальное;
- прогноз ожидания в секундах — на карточке и на экране лифта;
- сравнение с лестницей: сколько займёт лифт, сколько ступеньки и что быстрее;
- рекомендация «Ждать» или «Лестница» с учётом выбранного этажа;
- расписание пиков: плашка во время пика и предупреждение за 10 минут до него.

**Интерфейс**

- **два языка** — русский и английский, переключаются кнопкой в шапке;
- **работа без связи**: последние данные берутся из кэша, сверху появляется
  плашка с временем их получения;
- **пустой экран** с иллюстрацией и кнопкой «Повторить», а на первой
  загрузке — пульсирующие заглушки вместо карточек;
- **жалоба на лифт** — модалка снизу с причиной и комментарием;
- избранные лифты отмечаются звездой и идут первыми в списке;
- иконка лифта в шапке со счётчиком свободных кабин, тап — подъём к началу;
- плавная анимация цифр при обновлении данных;
- тёмная и светлая темы с тумблером, выбор запоминается.

Что хранится в браузере:

| Ключ `localStorage`    | Что |
|------------------------|-----|
| `tiu-go-theme`         | выбранная тема (`dark` / `light`) |
| `tiu-go-lang`          | язык интерфейса (`ru` / `en`) |
| `tiu-go-favorites`     | массив id избранных лифтов, например `[1, 3, 5]` |
| `tiu-go-destination`   | выбранный этаж назначения |
| `tiu-go-cache`         | последний удачный ответ сервера и время его получения |

Все лифты стоят по одному адресу — **Корпус 7, Мельникайте 70**. Он приходит
с сервера одним полем `address` и не переводится.

## Про `WEBAPP_URL`

Telegram открывает мини-приложение кнопкой `web_app` **только по HTTPS**.
Локальный `http://localhost:3000` для этого не подойдёт — поднимите туннель:

```bash
npx cloudflared tunnel --url http://localhost:3000
```

или

```bash
npx ngrok http 3000
```

Полученный `https://…` адрес впишите в `WEBAPP_URL` и перезапустите ботов.
Если в `WEBAPP_URL` указан `http://`, Telegram-бот автоматически отдаст
обычную ссылку вместо кнопки мини-аппа — удобно для отладки в браузере.

Сам мини-апп всегда доступен напрямую: <http://localhost:3000>

## API

### `GET /api/status`

Необязательный параметр `destination` — этаж, куда едет человек
(по умолчанию первый): `GET /api/status?destination=4`

```json
{
  "timestamp": "2026-10-06T08:00:00.000Z",
  "address": "Корпус 7, Мельникайте 70",
  "destination": 4,
  "refreshMs": 3000,
  "isPeak": false,
  "peakSoon": true,
  "minutesUntilPeak": 7,
  "peakLabel": "После первой пары",
  "peakKey": "afterFirst",
  "elevators": [
    {
      "id": 1,
      "number": 1,
      "cameraFloor": 1,
      "floors": 9,
      "currentFloor": 7,
      "occupancy": 2,
      "capacity": 5,
      "waiting": 1,
      "status": "busy",
      "recommendation": "wait",

      "waitTime": 15,
      "waitTimeText": "~15 сек",
      "elevatorTotal": 28,
      "elevatorTotalText": "~28 сек",
      "stairsTime": 36,
      "stairsTimeText": "~36 сек",
      "fasterOption": "elevator",
      "savedSeconds": 8
    }
  ]
}
```

Адрес один на все лифты и лежит в корне ответа. Названия лифтов приходят
номером (`number`), а подпись «Лифт 1» / «Elevator 1» собирает фронтенд —
так данные не привязаны к языку. То же с камерой: сервер отдаёт `cameraFloor`,
а строку «Камера: Холл, 1 этаж» строит интерфейс.

`peakKey` нужен для перевода подписи пика; `peakLabel` остаётся на русском
для тех, кто читает API напрямую.

### `POST /api/report`

Жалоба на лифт. Тело запроса:

```json
{ "elevatorId": 3, "reason": "noise", "comment": "Скрипит между 3 и 4 этажом" }
```

Ответ — `{ "success": true }`. Отчёт дописывается в
[`shared/data/reports.json`](shared/data/reports.json) с меткой времени; файл
создаётся при старте сервера, если его нет. Комментарий обрезается до 500 символов,
запрос без `elevatorId` или `reason` отклоняется с кодом 400.

Возможные `reason`: `broken`, `slow`, `noise`, `dirty`, `other`.

### Правила расчёта

Считает сервер, фронтенд только отображает.

**Статус кабины** (`status`) — по заполненности:

| Условие                       | status  | Цвет                |
|-------------------------------|---------|---------------------|
| `occupancy === 0`             | `ok`    | зелёный `#22C55E`   |
| от `1` до `capacity - 1`      | `busy`  | оранжевый `#F59E0B` |
| `occupancy >= capacity`       | `full`  | красный `#EF4444`   |

**Время** — всё считается от выбранного этажа назначения:

```
waitTime      = |currentFloor - destination| * 3   // доехать до вас
              + occupancy * 2                      // высадка тех, кто в кабине
              + waiting * 2                        // посадка очереди в холле

stairsTime    = |destination - 1| * 12             // пешком с первого этажа
elevatorTotal = waitTime + |currentFloor - destination| * 3 + occupancy * 2
savedSeconds  = |elevatorTotal - stairsTime|
```

`fasterOption` — `"elevator"`, `"stairs"` или `"equal"`. Константы
(3 / 2 / 12 секунд) лежат в начале [`shared/server.js`](shared/server.js).

Если этаж назначения выше, чем этажность конкретного корпуса, для этого лифта
берётся его верхний этаж — выше он физически не поедет.

**Рекомендация** (`recommendation`) — проверяется по порядку:

1. `wait` — на лифте выходит быстрее **и** ждать меньше 60 секунд;
2. `stairs` — лестница быстрее **или** ждать 90 секунд и дольше;
3. `wait` — во всех остальных случаях.

**Пиковые часы** задаются массивом `PEAK_HOURS`:

| Интервал      | Подпись             | `peakKey`     |
|---------------|---------------------|---------------|
| 08:20 – 08:50 | Утренний пик        | `morning`     |
| 13:30 – 13:50 | После первой пары   | `afterFirst`  |
| 15:20 – 15:40 | После второй пары   | `afterSecond` |
| 17:10 – 17:30 | После третьей пары  | `afterThird`  |

Если текущее время внутри интервала — `isPeak: true`. Если до начала ближайшего
пика осталось 10 минут или меньше — `peakSoon: true` и `minutesUntilPeak`.

## Заметки по боту MAX

В файле `tiu go max/index.js` оставлены `TODO`-комментарии:
точные endpoint'ы, структуру событий и типы кнопок нужно сверить с
официальной документацией — **https://dev.max.ru/docs**.

Сейчас используется схема:

- `GET /updates` — long polling событий;
- `POST /messages` — отправка сообщения;
- вложение `inline_keyboard` с кнопкой типа `link`.

Базовый адрес API можно переопределить переменной `MAX_API_BASE` в `.env`.

через `access_token` рабочие. Остальные поля всё же сверьте с документацией.

## Оформление

Интерфейс минималистичный, с крупной типографикой и сгруппированными карточками.
Все цвета вынесены в CSS-переменные в `:root`; светлая тема переопределяет их
в `:root[data-theme='light']` — хардкодных цветов в правилах нет.

| Роль                  | Тёмная    | Светлая   |
|-----------------------|-----------|-----------|
| Фон                   | `#0B0D12` | `#F7F8FA` |
| Карточки              | `#161A22` | `#FFFFFF` |
| Границы               | `#232833` | `#E5E7EB` |
| Основной текст        | `#FFFFFF` | `#0B0D12` |
| Второстепенный текст  | `#9CA3AF` | `#6B7280` |
| Акцент                | `#5B8DEF` | `#4F46E5` |

Статусы в обеих темах одинаковые: `#22C55E` / `#F59E0B` / `#EF4444`.

Отдельные переменные заведены под новые элементы: `--peak-bg` / `--peak-fg`
(плашка активного пика), `--peak-soon-bg` / `--peak-soon-fg` (предупреждение)
и `--fav-border` (рамка избранного лифта). Жёстко прописанных цветов в правилах нет.

### Переключение темы

Круглый тумблер в правом верхнем углу: ☀ — светлая, 🌙 — тёмная.
Выбор сохраняется в `localStorage` под ключом `tiu-go-theme` и восстанавливается
при следующем открытии. Если сохранённого выбора нет, тема берётся из системной
настройки (`prefers-color-scheme`), а внутри Telegram и MAX — из темы клиента;
по умолчанию тёмная. Тема ставится ещё до первой отрисовки маленьким скриптом
в `<head>`, иначе при светлой теме мелькал бы тёмный фон.

### Анимация цифр

При обновлении данных числа не подменяются мгновенно, а «перекатываются» к новому
значению за 400 мс на `requestAnimationFrame` с замедлением к концу, плюс короткий
подскок через класс `.number-changed`. Анимируются заполненность кабины, очередь,
прогноз ожидания, текущий этаж и счётчик свободных лифтов в шапке.

Если значение не изменилось, не происходит ничего — автообновление раз в три
секунды не дёргает интерфейс. Предыдущая анимация того же элемента прерывается,
поэтому кадры не наслаиваются.

### Анимация лифта

В каждой карточке слева от цифры этажа — шахта (6×60 px) с кабиной 8×8 px
акцентного цвета и рисками по числу этажей корпуса. Кабина едет по шахте
плавно: `transition: bottom 0.6s ease-in-out`. Рядом стрелка направления —
▲ вверх, ▼ вниз, • стоит; направление вычисляется на фронтенде сравнением
с этажом на предыдущем обновлении. На экране лифта шахта крупнее: 12×200 px
с кабиной 16×16 px.

Чтобы переход вообще срабатывал, карточки строятся один раз, а дальше в них
обновляются только значения (`buildTile` / `updateTile` в
[`shared/public/app.js`](shared/public/app.js)). При полной перерисовке разметки
каждые три секунды CSS-переход не успевал бы стартовать.

### Матовое стекло

`backdrop-filter` стоит только там, где под панелью реально что-то проезжает:

| Где | Что происходит |
|-----|----------------|
| Навбар списка | проявляется, когда крупный заголовок уходит под него |
| Навбар экрана лифта | закреплён сверху, контент прокручивается под ним |
| Нижний тулбар с кнопкой «Обновить» | закреплён снизу, карточки уходят под него |
| Плашка «Нет связи с сервером» | висит поверх списка |
| LIVE и «Ожидают: N» на кадре камеры | тёмное стекло поверх изображения |

Карточки остаются плотными. Если `backdrop-filter` не поддерживается,
через `@supports` панели становятся непрозрачными.

## Локализация

Интерфейс переключается между русским и английским кнопкой `RU` / `EN`
в шапке. Выбор сохраняется в `localStorage` под ключом `tiu-go-lang`.

Все строки лежат в [`shared/public/i18n.js`](shared/public/i18n.js) —
один объект с двумя словарями:

```js
t('ru', 'detail.recommendation')            // 'Рекомендация'
t('en', 'peak.soon', { n: 7, label: '…' })  // '… starts in 7 min'
```

Статические подписи размечены в HTML атрибутом `data-i18n`, при смене языка
приложение проходит по ним и подставляет перевод; `data-i18n-aria` делает то же
для `aria-label`. Динамические строки (сводка, бейджи, вердикт сравнения,
подписи пиков) собираются в `app.js` через тот же словарь.

Множественное число учитывается отдельно для каждого языка: в русском три формы
(1 лифт, 2 лифта, 5 лифтов), в английском две. Если ключа в словаре не окажется,
подставится русский вариант, а в крайнем случае — сам ключ, чтобы пропажа строки
была заметна и ничего не падало.

**Что не переводится:** адрес «Корпус 7, Мельникайте 70». Данные с сервера
приходят без языковых строк — только числа (`number`, `cameraFloor`) и ключи
(`peakKey`, `reason`), поэтому смена языка не требует повторного запроса.

## Кэш и офлайн

Каждый удачный ответ сервера складывается в `localStorage` под ключом
`tiu-go-cache` вместе с временем получения.

Если запрос не удался (нет сети или сервер ответил ошибкой):

- **кэш есть** — показываем последние данные, а сверху появляется янтарная
  плашка «Нет связи · данные от 12:00:03». Индикатор в шапке становится красным,
  компактный навбар опускается под плашку;
- **кэша нет** — показываем пустой экран с иллюстрацией лифта, подписью
  «Не удалось связаться с сервером» и кнопкой «Повторить»
  (на две секунды превращается в «Пробуем…»).

При следующем удачном запросе плашка исчезает сама, кэш перезаписывается.

Пока идёт самый первый запрос и кэша ещё нет, вместо карточек показываются
пульсирующие заглушки. Если сервер вернул пустой список лифтов, открывается тот
же пустой экран, но с подписью «Пока нет данных о лифтах».

## Отчёты о проблемах

На экране лифта есть кнопка «Сообщить о проблеме». Она открывает модалку снизу
с пятью причинами (не работает, долго едет, шумит, грязно, другое),
необязательным комментарием и кнопкой отправки. После успешной отправки модалка
уезжает вниз, а внизу экрана на три секунды всплывает «Спасибо! Мы передали
информацию».

Отчёт уходит в `POST /api/report` и дописывается в
[`shared/data/reports.json`](shared/data/reports.json):

```json
[
  {
    "timestamp": "2026-10-06T08:26:07.385Z",
    "elevatorId": 1,
    "reason": "noise",
    "comment": "Скрипит между 3 и 4 этажом"
  }
]
```

На сервер уходит ключ причины, а не её перевод, — отчёты не зависят от языка
интерфейса. Если отправка не удалась, модалка всё равно закрывается, а в тосте
появляется сообщение об ошибке.

снимает три экрана, а потом отрисовывает из них готовые картинки:

| Файл | Размер | Для чего |
|------|--------|----------|
| `main-dark.png`   | 780×1688 | главный экран, тёмная тема |
| `main-light.png`  | 780×1688 | главный экран, светлая тема |
| `detail-dark.png` | 780×1688 | экран лифта с камерой |
| **`mockup.png`**      | 3840×2160 | **готовый слайд 16:9: три айфона на светлом фоне** |
| **`mockup-dark.png`** | 3840×2160 | **тот же слайд на тёмном фоне** |
| `phone-main-dark.png`   | 828×1736 | один телефон, фон прозрачный |
| `phone-main-light.png`  | 828×1736 | один телефон, фон прозрачный |
| `phone-detail-dark.png` | 828×1736 | один телефон, фон прозрачный |

**В презентацию** вставляйте `mockup.png` или `mockup-dark.png` — они уже
размером со слайд 1920×1080 (сохранены в двойном разрешении, чтобы не мылились
на проекторе). Если хотите свою вёрстку слайда — берите `phone-*.png`:
у них прозрачный фон, телефон можно положить на любую подложку.

**Перерисовать только мокапы** (сервер не нужен, кадры берутся готовые):

```bash
npm run mockup
```

Это удобно, когда правите заголовок или фон в
[`screenshots/mockup.html`](screenshots/mockup.html). Файл открывается и руками
в браузере; параметры в адресе: `?theme=dark` — тёмный слайд,
`?bare=main-dark` — один телефон без фона.

Если сервер поднят на другом порту:

```bash
TIU_GO_URL=http://localhost:3005 npm run screenshots
```

### Что дорисовано в рамке

Сами скриншоты — настоящие, снятые с работающего приложения. Рамка добавляет
только то, что на реальном телефоне рисует система: корпус iPhone 14, «остров»,
строку состояния (время 9:41, связь, Wi-Fi, батарея) и полоску «домой».
Перед съёмкой скрипт подставляет приложению безопасные зоны сверху и снизу —
в браузере `env(safe-area-inset-*)` равен нулю, и без этого «остров» перекрыл бы
кнопку «Назад».

Файлы перезаписываются при каждом запуске команды.
