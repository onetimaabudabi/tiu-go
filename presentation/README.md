# Презентация для инвесторов

Двенадцать слайдов, которые собираются кодом, а не правятся руками в
PowerPoint. Числа берутся из тех же моделей, что и отчёты проекта,
поэтому после пересчёта моделей достаточно пересобрать колоду.

```bash
npm run presentation          # собрать output/TIU_GO_Presentation.pptx
npm run presentation:preview  # отрисовать PNG и проверить вёрстку
```

## Что где лежит

| Файл | Зачем |
|------|-------|
| [`content.js`](content.js) | весь текст и все числа — правится в первую очередь |
| [`theme.js`](theme.js) | цвета, шрифт, сетка, типографика |
| [`lib/layout.js`](lib/layout.js) | карточки, метрики, списки поверх pptxgenjs |
| [`lib/assets.js`](lib/assets.js) | логотип без белой подложки, пути к картинкам |
| [`slides/01…12`](slides) | по модулю на слайд |
| [`generate.js`](generate.js) | готовит ассеты и собирает .pptx |
| [`preview.js`](preview.js) | предпросмотр без PowerPoint |

## Предпросмотр

`preview.js` подменяет pptxgenjs записывающей заглушкой, прогоняет те же
модули из `slides/` и рисует результат в PNG через node-canvas. Это не
пиксель в пиксель PowerPoint, но этого хватает, чтобы ловить три вещи:

- текст, который не влез в свой блок (скажет, какая высота нужна);
- два текстовых блока, наехавших друг на друга;
- контент, заехавший в полосу подвала.

Выход: `output/preview/slide-NN.png` и список замечаний. Сейчас замечаний нет.

## Откуда взяты числа

| Источник | Что даёт |
|----------|----------|
| `shared/params.json` | этажность, число лифтов, люди, камера |
| `tech-model/output/data/*.json` | пропускная способность, лишние остановки, ошибки детекции |
| `npm run math:sim` / `math:queue` / `math:optimize` / `math:sensitivity` | ожидание, время подъёма, очередь, чувствительность |
| `docs/Бизнес_расчеты_TIU_GO.docx` | смета, экономия часов, окупаемость |
| `ПАСПОРТ_ПРОЕКТА.md` | рынки НТИ, конкуренты, стейкхолдеры, риски |

Техническая модель сохраняет результаты в JSON, и `content.js` читает их
на каждой сборке. Математическая модель JSON не пишет — её числа лежат в
блоке `MATH` константами с пометкой, какой командой получены. Пересчитали
модель — обновите этот блок.

## Расхождения в исходных данных

Там, где документы проекта расходятся, на слайды пошли более свежие и
более осторожные числа.

| Показатель | Бизнес-расчёты | Модели | Взято | Почему |
|---|---|---|---|---|
| Людей в корпусе | 1 500 | 1 150 | **1 150** | `shared/params.json` — единственный источник параметров |
| Поездок в день | 2 000 | 4 600 | **4 600** | 1 150 × 4 поездки, так же считает имитация |
| Ожидание без системы | 90 с | 88,1 с | **88,1 с** | результат имитации на 500 прогонов |
| Ожидание с системой | 30 с | 68,4 с | **68,4 с** | 30 с — слишком оптимистично, модель даёт 68,4 |
| Пропускная способность | — | 522 чел/ч | **522 чел/ч** | три рабочих лифта; в `math-model/README.md` осталось старое число 762 для шести |
| Пиковые интервалы | 08:20–08:50, 13:30–13:50 | по расписанию пар | **по расписанию** | `shared/params.json`, поле `peakIntervals` |

Отдельно про экономию часов. Бизнес-расчёты дают **5 000 ч в год**
(60 с × 1 500 человек × 1 поездка × 200 дней). По текущим параметрам
вышло бы 48,6 с × 4 600 поездок × 200 дней ≈ **12 400 ч** — в два с
половиной раза больше. На слайдах оставлено 5 000 ч: для инвестора
заниженная цифра безопаснее завышенной, а порядок величины один и тот же.
