# Математическая модель TIU GO

Научное обоснование проекта: шесть моделей, которые проверяют количественно,
даёт ли информирование пассажира измеримый эффект и за счёт чего именно.

Это не экономический расчёт — он лежит в [`docs/`](../docs). Здесь физика,
теория массового обслуживания, имитация и оптимизация.

## Что внутри

| Файл | Модель | Что отвечает |
|------|--------|--------------|
| [`params.js`](params.js) | — | все параметры в одном месте |
| [`01-queueing-model.js`](01-queueing-model.js) | M/M/c, формулы Эрланга | хватает ли пропускной способности |
| [`02-simulation.js`](02-simulation.js) | Монте-Карло, 1000 дней | что происходит в реальном дне |
| [`03-utility-model.js`](03-utility-model.js) | теория полезности, логит | кто выберет лестницу и почему |
| [`04-elevator-physics.js`](04-elevator-physics.js) | физика движения кабины | сколько людей в час увезут лифты |
| [`05-sensitivity.js`](05-sensitivity.js) | анализ чувствительности | какой параметр решает всё |
| [`06-optimization.js`](06-optimization.js) | оптимизация потока | как делить поток правильно |
| [`07-report.js`](07-report.js) | — | собирает отчёт Word |

## Запуск

```bash
npm run math:all
```

Полный прогон занимает около полуминуты. По отдельности:

```bash
npm run math:physics      # физика движения кабины
npm run math:queue        # M/M/c
npm run math:sim          # имитация 1000 дней
npm run math:utility      # функция полезности
npm run math:sensitivity  # чувствительность
npm run math:optimize     # оптимизация
npm run math:report       # отчёт (запускает всё остальное)
```

Каждый скрипт самодостаточен: порядок запуска не важен, нужные расчёты
он выполнит сам.

## Связи между моделями

Физика задаёт интенсивность обслуживания μ, из неё теория очередей получает
пропускную способность, функция полезности определяет порог терпения для
имитации, а оптимизация использует и то, и другое:

```
04-физика ──μ──> 01-очереди ──ν──> 06-оптимизация
    │                                    ▲
    └──время рейса──> 02-имитация        │
                          ▲              │
03-полезность ──порог терпения──┘────────┘
```

## Главные результаты

**Лифты не справляются с пиком по физике, а не по организации.** Пропускная
способность шести кабин — 762 чел/ч, спрос в утренний пик — 2520 чел/ч.
Дефицит троекратный, и расписанием его не закрыть.

**Система уже саморегулируется, но дорогой ценой.** Люди уходят на лестницу,
когда ожидание становится невыносимым, — но уходят, уже потеряв время.
Имитация показывает: 36 секунд на человека тратится впустую, просто на
стояние перед отказом от затеи.

**Поведение важнее оборудования.** Анализ чувствительности: рост доли
следующих совету с 0 до 90% меняет результат на 45%, а увеличение числа
кабин с четырёх до восьми — всего на 9%. Информирование окупается лучше,
чем закупка лифтов.

## Оговорки

Модель опирается на оценки, а не на замеры: интенсивность потока, время
подъёма по лестнице и терпение людей взяты из расписания и здравого смысла.
Натурные измерения изменят абсолютные значения, но вряд ли изменят порядок
величин и соотношения между параметрами — именно поэтому выводы
сформулированы в относительных терминах.

Отдельно стоит отметить два места, где модель отступает от классических
формул осознанно:

- **μ считается на пассажира, а не на рейс.** В кабине едет несколько
  человек, поэтому μ = P / T_рейс. При μ = 1 / T_рейс система оказалась бы
  перегружена даже в спокойные часы, чего в реальности не происходит.
- **Ожидание при перегрузке считается детерминированной моделью.** Формулы
  Эрланга выведены для стационарного режима и при ρ ≥ 1 неприменимы:
  очередь растёт неограниченно. Для пиков используется накопление очереди
  на конечном интервале.
